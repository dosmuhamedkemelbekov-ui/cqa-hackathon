# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker (команда DOSTEAM). Система оценивает работу оператора в чатах и звонках на русском, казахском и английском языках по настраиваемому чек-листу. По каждому критерию она показывает ответ, баллы, объяснение и реплику-доказательство. Оценку можно оспорить: супервизор принимает решение, итог пересчитывается.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env, затем впишите ключ модели (см. ниже)
python scripts/check_llm.py       # проверка ключа и модели — должно быть «OK»
python scripts/load_dev.py DEV    # набор DEV из API организаторов; без сети: python scripts/load_dev.py data/dev.json
python -m uvicorn backend.app:app --port 8000
```

Откройте http://localhost:8000. На Windows вместо `python` используйте `py`. Если диалоги ещё не загружены, главная страница предложит кнопку «Загрузить набор DEV».

## Настройка модели

Решение сдаётся на Google Gemini через OpenAI-совместимый API. Бесплатный ключ: [aistudio.google.com](https://aistudio.google.com/apikey) → Create API key. Файл `.env`:

```
OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
OPENAI_API_KEY=<ключ Gemini>
CQA_MODEL=gemini-3.5-flash
CQA_FALLBACK_MODEL=gemini-3.5-flash-lite   # резерв, если у основной модели кончится дневной лимит
CQA_EVAL_MODE=single                       # один вызов модели на диалог — все критерии сразу
CQA_RPM=4                                  # не больше 4 запросов в минуту (бесплатный тариф)
CQA_TEAM_NAME=DOSTEAM
```

Другие варианты (готовые примеры — в `.env.example`):

- **OpenAI или любой OpenAI-совместимый API** — `OPENAI_API_KEY`, `CQA_MODEL` (по умолчанию `gpt-4.1`);
- **локальная модель** (Ollama, LM Studio, vLLM) — `OPENAI_BASE_URL=http://localhost:11434/v1`;
- **Claude** — `CQA_PROVIDER=anthropic`, `ANTHROPIC_API_KEY`, `CQA_CLAUDE_MODEL`.

## Как пользоваться

Интерфейс состоит из четырёх разделов (меню слева):

- **Диалоги** — список с фильтрами, транскрипт и карточка оценки. Чтобы оценить диалог, выберите его и нажмите «Оценить ИИ». Блок «Почему снижена оценка» показывает потери баллов. Кнопка «Перейти к фрагменту» подсвечивает реплику-доказательство, «Оспорить оценку» подаёт апелляцию.
- **Чек-листы** — критерии, тип ответа, шкала, вес, доступность N/A и правила для ИИ. Кнопка «Применить и переоценить диалоги» сохраняет новую версию и применяет её к набору.
- **Апелляции** — очередь для супервизора (роль переключается внизу меню). «Рассмотреть» открывает спорный критерий: супервизор подтверждает или меняет оценку с указанием причины, итог пересчитывается.
- **Аналитика** — очередь проверки по риску, журнал для регулятора, грубые ошибки с объяснениями и цитатами, точность против эталона и сдача `results.json`.

Новый диалог можно добавить вручную: «+ Новый диалог» → текст в формате `MM:SS спикер: текст` или аудиофайл. Аудио распознаётся через Whisper, поэтому для него нужен ключ OpenAI: `CQA_STT_API_KEY=<ключ OpenAI>` — распознавание пойдёт в OpenAI, даже если оценивает Gemini (другой адрес — `CQA_STT_BASE_URL`).

## Сдача результатов

Результаты лежат в `results/dev/results.json` и `results/prod/results.json` в формате организаторов JSON 1.0:

- коды критериев `contact … critical`, значения `true` / `false` / `null` (N/A) и ступени шкал;
- `evidence_turns` — номера реплик с 1 по исходному массиву транскрипта;
- `final_score` считается по правилам чек-листа, `critical_flag` совпадает с `critical`;
- диалог, который не удалось оценить, записывается со `status: "error"` и причиной, а не пропускается.

Перед записью файл проверяется: все 8 критериев, допустимые значения, без повторов ID, в `prod` ровно 10 записей.

**DEV:**

```bash
python scripts/batch_eval.py DEV
python scripts/export_results.py DEV --team "DOSTEAM"    # → results/dev/results.json + проверка формата
```

Или в интерфейсе: «Аналитика» → «Сдача результатов · JSON 1.0» → набор DEV → «Сохранить в results/dev/results.json и проверить».

**Контрольный набор (последний час)** — одна команда:

```bash
python scripts/run_prod.py <group_id> --team "DOSTEAM" --push
```

Скрипт загружает набор из API, оценивает 10 диалогов активным чек-листом (до двух повторов при сбоях), записывает и проверяет `results/prod/results.json`, затем делает `git commit` и `git push`. Если API недоступен, сохраните его ответ в файл и запустите `python scripts/run_prod.py --file prod.json --team "DOSTEAM" --push`. После отправки убедитесь, что файл виден на GitHub.

Если критерий заменён и должен попасть в выгрузку под официальным кодом, укажите код в «Чек-листы» → «Правила ▸» → «Код в выгрузке results.json».

## Как это работает

```
Фронтенд (HTML/CSS/JS, без сборки) ──REST──> FastAPI ──> SQLite
                                                 ├──> LLM (Gemini / OpenAI / Claude / локальная)
                                                 └──> правила (backend/rules.py)
```

1. **Предобработка** (`backend/preprocess.py`). Реплики получают id `m0…mN`, время приводится к секундам: у чатов из `MM:SS`, у звонков из ISO 8601 с учётом пауз записи. В звонках таймкод транскрипта — **конец** фразы (на DEV так выходит ~2,2 слова/с, иначе ~5,8): начало фразы оценивается по числу слов, и плеер переходит к началу реплики. Код вычисляет факты, в которых не стоит полагаться на модель: первую реплику оператора, передачу диалога оператору, системное подтверждение личности, событие завершения, долгие паузы.
2. **Оценка** (`backend/evaluator.py`). Промпт собирается из настроек критерия, поэтому новый или изменённый критерий работает без правок кода. Модель сначала приводит доказательства и рассуждение, затем выбирает ответ только из допустимых значений; ответ проверяется по JSON Schema. Режимы: `single` — все критерии одним вызовом, `per_criterion` — отдельный вызов на критерий.
3. **Правила** (`backend/rules.py`) проверяют объективные факты и исправляют ответ модели, если он им противоречит (см. таблицу ниже).
4. **Итог** (`backend/scoring.py`) считает код, а не модель. «Да» даёт полный вес, «Нет» — ноль, шкала пересчитывается пропорционально весу. Вес критериев с N/A перераспределяется между применимыми, максимум остаётся 100. Итог округляется до двух знаков. Грубая ошибка отмечается отдельным флагом и итог не обнуляет.
5. **Апелляция и версии.** Решение супервизора пересчитывает итог; исходная оценка ИИ сохраняется. Каждое сохранение чек-листа создаёт версию, каждая оценка хранит снимок чек-листа, по которому её сделали.

### Правила поверх модели

| Критерий | Правило |
|---|---|
| Установление контакта | В первой реплике оператора есть приветствие на языке клиента **и** имя → «Да», иначе «Нет» |
| Выявление потребности | Оператор не задал ни одного уточняющего вопроса → «Да» модели меняется на N/A; консультация N/A → N/A |
| Идентификация | Системное «Личность клиента подтверждена» → N/A модели меняется на «Да» |
| Завершение | «Оператор закрыл чат» → «Нет»; последняя реплика оператора — только вежливость и прощание → «Нет»; оператор не попрощался → «Нет»; чат оборвался сразу после реплики клиента → N/A |

Правила срабатывают только для критериев с исходной формулировкой и видны в карточке (значок ⚙ с причиной). Проверка на всех 65 диалогах DEV: `python scripts/check_rules.py` — 153 исправления к эталону, 0 ошибок. Отключить правила: `CQA_RULES=0`.

## Точность

`gold/gold.json` — эталонная разметка 65 диалогов DEV, сделанная командой вручную по чек-листу (спорные ответы помечены в `uncertain`). Эталон используется только для замера и в промпт модели не попадает.

| Шаг (40 диалогов DEV, режим `single`) | Совпадение ответов | Средняя ошибка итога |
|---|---|---|
| Gemini 3.5 Flash Lite + базовые правила | 91,9% | 4,15 балла |
| + правила завершения и выявления потребности | 95,3% | 3,15 балла |
| + уточнения в промпте | 95,9% | 2,93 балла |
| + Gemini 3.5 Flash на 8 сложных диалогах | 97,8% | 1,50 балла |

```bash
python scripts/accuracy.py --details   # совпадение по критериям, ошибка итога, список расхождений
python scripts/reapply_rules.py DEV    # применить правила к готовым оценкам без вызовов модели
```

Обновлённый регламент из `checklists/default.json` применяется к базе автоматически при запуске сервера, если чек-лист не меняли вручную. Если меняли — «Чек-листы» → «Вернуть регламент Freedom» → «Применить».

## Чем отличается

- **Правила поверх ИИ** — объективные факты проверяются кодом, срабатывание видно в карточке.
- **Проверка цитат** — каждая цитата-доказательство сверяется с текстом реплики; выдуманная помечается ⚠.
- **Самопроверка ИИ** (режим `per_criterion`, `CQA_VERIFY=1`) — рискованные ответы перепроверяет второй проход.
- **Обучение на апелляциях** — решение супервизора становится прецедентом для следующих оценок других диалогов.
- **Тесты для нового критерия** — «Чек-листы» → «Правила ▸» → «🧪 Проверить критерий на тестах»: ИИ пишет 5–7 коротких диалогов с известным ответом и проверяет, правильно ли понял критерий, до применения к реальным диалогам.
- **Очередь проверки по риску** — что супервизору смотреть первым; система ничего не пропускает, только сортирует. Замер по эталону DEV (проблема = грубая ошибка или итог ниже 70): топ-5 — 5 из 5 реальных проблем (случайно ≈ 1,2), все 16 проблем — за 28 просмотров (по баллу ИИ — 32, случайно ≈ 62). Веса риска заданы заранее, под эталон не подбирались.
- **Профиль разговора** — под дорожками речи, по таймкодам, без ИИ: доля речи, темп, возможные перебивания и тишина оператора (звонки), ожидание ответа и длина ответов (чаты); клик ведёт к реплике.
- **Журнал для регулятора** — каждое событие фиксируется в цепочке SHA-256; «Аналитика» → «Журнал для регулятора» → «Проверить целостность» показывает правку базы в обход системы. Демонстрация: `python scripts/audit_demo.py tamper p1-ru-002`, затем `python scripts/audit_demo.py restore`.
- **«Суд» из двух ИИ для спорного критерия** — в карточке критерия «⚖ Суд ИИ»: два независимых вызова модели — обвинитель отстаивает самый строгий обоснованный ответ, защитник — самый благоприятный для оператора, оба с цитатами (сверяются с текстом) и «слабым местом оппонента»; если позиция не защищается, сторона это признаёт. Решает супервизор: «Принять позицию» подставляет ответ и довод в вердикт. Учитывается комментарий оператора из апелляции. 2 вызова ИИ.
- **Коучинг оператора** — 2–3 совета со ссылкой на реплику и готовой фразой на языке клиента.
- **Резервная модель** — при дневном лимите основной оценка продолжается резервной; обе модели указываются в `results.json`.
- **Готовность к Dynamics 365** — один файл `frontend/index.html`; для встраивания как HTML web resource задайте `window.CQA_API_BASE` — адрес сервиса.

## Модель и стоимость

| Режим | Вызовов модели на диалог |
|---|---|
| `single` (сдача) | 1; критерии, которые модель вернула некорректно, дооцениваются по одному |
| `per_criterion` | по одному на критерий (8) + самопроверка рискованных ответов |

На бесплатном тарифе Gemini стоимость оценки — $0. Для платных моделей стоимость считается автоматически и видна в карточке: цены Claude встроены, для остальных задаются в `CQA_PRICE_INPUT_PER_M`, `CQA_PRICE_CACHED_INPUT_PER_M`, `CQA_PRICE_OUTPUT_PER_M`. Для OpenAI и Claude транскрипт кэшируется как общий префикс промпта для всех критериев диалога.

| Переменная `.env` | По умолчанию | Что делает |
|---|---|---|
| `CQA_EVAL_MODE` | `per_criterion` | `single` — все критерии одним вызовом |
| `CQA_VERIFY` | `1` | самопроверка рискованных ответов (режим `per_criterion`) |
| `CQA_SAMPLES` | `1` | прогонов на критерий (>1 — голосование, точнее и дороже) |
| `CQA_RULES` | `1` | правила поверх ответов модели |
| `CQA_FALLBACK_MODEL` | — | резервная модель при дневном лимите основной |
| `CQA_CONCURRENCY` / `CQA_DIALOG_CONCURRENCY` | `16` / `4` | параллельных запросов к модели / диалогов в пакете |
| `CQA_RPM` | `0` | лимит запросов в минуту (0 — без лимита) |
| `CQA_LLM_TIMEOUT` | `180` | тайм-аут запроса к модели, с |
| `CQA_PRECEDENTS` | `6` | сколько прецедентов супервизора по критерию подмешивать в промпт |
| `CQA_TEAM_NAME` | — | название команды в `results.json` |
| `CQA_STT_MODEL` / `CQA_STT_API_KEY` | `whisper-1` / ключ модели | распознавание загруженных аудиозаписей |

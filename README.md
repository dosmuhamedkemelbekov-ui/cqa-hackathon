# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker. Система автоматически оценивает работу оператора в чатах и звонках по настраиваемому чек-листу: показывает баллы, объяснения и реплики-доказательства, а также поддерживает апелляцию и пересмотр оценки.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env — впишите ключ модели (ниже)
python scripts/check_llm.py       # проверка ключа и модели: должно быть «OK»
python scripts/load_dev.py DEV    # DEV-набор из API организаторов (или: python scripts/load_dev.py data/dev.json)
python -m uvicorn backend.app:app --port 8000
```

Откройте http://localhost:8000. На Windows вместо `python` используйте `py`. Без загруженных диалогов главная страница сама предложит «Загрузить набор DEV».

**Модель, на которой сдаём** — Google Gemini через OpenAI-совместимый API (бесплатный ключ: aistudio.google.com → Get API key):

```
OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
OPENAI_API_KEY=<ключ Gemini>
CQA_MODEL=gemini-3.5-flash
CQA_FALLBACK_MODEL=gemini-3.5-flash-lite   # при дневном лимите основной оценка продолжается этой моделью
CQA_EVAL_MODE=single                       # 1 вызов модели на диалог (все критерии сразу)
CQA_RPM=4                                  # не больше 4 запросов в минуту (бесплатный тариф)
CQA_TEAM_NAME=DOSTEAM
```

Подходит и любая другая модель: OpenAI, Claude (`CQA_PROVIDER=anthropic`), локальная через Ollama (`OPENAI_BASE_URL=http://localhost:11434/v1`) — см. `.env.example`.

Контрольный набор: `python scripts/run_prod.py <group_id> --team "DOSTEAM" --push` (подробно — ниже) или из интерфейса: код набора в меню → «Загрузить» → «Оценить ИИ».

## Сдача результатов (формат организаторов JSON 1.0)

Файлы лежат в `results/dev/results.json` и `results/prod/results.json`. Выгрузка делает всё по приложению к гайду: коды критериев `contact … critical`, значения `true/false/null` и ступени шкал, `evidence_turns` нумеруются с 1 по исходному массиву транскрипта, итог пересчитывается по правилам чек-листа (N/A → перераспределение веса, округление до 2 знаков), `critical_flag` совпадает с `critical`. Диалог, который не удалось оценить, попадает в файл со `status: "error"`, а не исчезает и не получает ноль.

```bash
python scripts/batch_eval.py DEV                       # оценить DEV
python scripts/export_results.py DEV --team "Команда"  # → results/dev/results.json + проверка формата
python scripts/export_results.py --check results/dev/results.json
```

В интерфейсе то же самое: «Точность и сводка» → «Сдача результатов · JSON 1.0» → «Сохранить и проверить».

### Контрольный этап: последний час

1. Заранее: в `.env` задан рабочий ключ модели (проверьте баланс!) и `CQA_TEAM_NAME`; `python scripts/accuracy.py` показывает приемлемую точность на DEV.
2. Получив `group_id`, выполните **одну команду**:
   ```bash
   python scripts/run_prod.py <group_id> --team "Команда" --push
   ```
   Она загружает набор из API, оценивает 10 диалогов активным чек-листом (до двух повторов при сбоях), пишет `results/prod/results.json`, проверяет формат (ровно 10 записей, ID совпадают с API) и делает `git commit` + `git push`.
3. Если API недоступен: сохраните ответ API в файл и запустите `python scripts/run_prod.py --file prod.json --team "Команда" --push`.
4. Откройте файл на GitHub и убедитесь, что push прошёл до стоп-кода.

Отдельная проверка с заменой критерия: «Настройки чек-листа» → изменить критерий → «Применить и переоценить диалоги». Если заменяемый критерий должен попасть в файл под официальным кодом, укажите его в поле «Код в выгрузке results.json».

## Гибрид: правила + LLM

Смысловые критерии оценивает модель, а объективные факты страхуют детерминированные правила (`backend/rules.py`):

| Критерий | Правило |
|---|---|
| Установление контакта | в первой реплике оператора есть приветствие на языке клиента **и** имя → Да, иначе Нет |
| Идентификация | системное «Личность клиента подтверждена» → N/A модели исправляется на Да |
| Завершение | «Оператор закрыл чат» → Нет; чат оборвался сразу после реплики клиента → N/A |
| Выявление потребности | консультация N/A (запрос не сформулирован) → N/A |

Правила проверены на всех 65 диалогах DEV (`py scripts/check_rules.py`: 0 ответов, уведённых от эталона), применяются только к критериям с исходной формулировкой (заменённый критерий не трогают) и видны в карточке (значок ⚙ с причиной). Отключить: `CQA_RULES=0`. В промпт добавлены обобщённые примеры трактовки по каждому смысловому критерию.

## Точность против эталона

`gold/gold.json` — эталонная разметка всех 65 диалогов DEV, сделанная вручную по чек-листу (спорные ответы помечены в `uncertain`). Эталон используется только для замера, в промпты модели не подаётся.

```bash
python scripts/accuracy.py --details   # совпадение по критериям, MAE итога, список расхождений
python scripts/accuracy.py --sure      # только бесспорные ответы эталона
```

Уточнения к правилам в `checklists/default.json` применяются к базе, созданной заново. В уже существующей базе нажмите в настройках «Вернуть регламент Freedom» → «Применить и переоценить диалоги».

## Как это работает

```
Фронтенд (HTML/CSS/JS, без сборки) ──REST──> FastAPI ──> SQLite
                                                └──> LLM (любой OpenAI-совместимый API)
```

1. **Предобработка** (`backend/preprocess.py`). Каждой реплике присваивается id `m0…mN`. Время приводится к секундам: у чатов из MM:SS, у звонков из ISO 8601. Для звонков рассчитывается позиция реплики в аудиозаписи с учётом пауз записи. Код также вычисляет факты, на которые лучше не полагаться на LLM: первую реплику оператора, момент передачи диалога оператору, системное подтверждение личности, событие завершения и долгие паузы оператора.
2. **Оценка** (`backend/evaluator.py`). На каждый критерий делается отдельный вызов LLM, вызовы идут параллельно. Промпт собирается из настроек критерия: правило, условие N/A, ступени шкалы, уточнения. Поэтому новый или изменённый критерий начинает работать без правок кода. Ответ модели проходит проверку по JSON Schema: модель сначала приводит доказательства (id реплик и цитаты) и рассуждение, затем выбирает ответ только из допустимых значений. Если задать `CQA_SAMPLES>1`, на каждый критерий делается несколько прогонов: для «Да/Нет» побеждает большинство, для шкал берётся медиана.
3. **Расчёт итога** (`backend/scoring.py`) выполняется кодом, без участия LLM, строго по правилам чек-листа. «Да» даёт полный вес, «Нет» — ноль. Шкальная оценка пересчитывается пропорционально весу. Вес критериев с N/A перераспределяется между применимыми критериями так, чтобы максимум остался 100. Итог округляется до двух знаков (ROUND_HALF_UP). Грубая ошибка отмечается отдельным флагом.
4. **Апелляция.** Пользователь оспаривает критерий и пишет комментарий. Проверяющий видит спорную оценку, обоснование ИИ и фрагмент диалога, затем подтверждает оценку или меняет её с указанием причины. Итог пересчитывается, при этом сохраняются и исходная оценка ИИ, и финальный результат.
5. **Чек-лист.** Каждое сохранение создаёт новую версию. Каждая оценка хранит снимок того чек-листа, по которому её сделали. Кнопка «Сохранить и переоценить диалоги» применяет новую версию к набору.

## Чем отличается

- **Самопроверка ИИ.** Рискованные ответы («Нет», N/A, неполный балл, грубая ошибка, низкая уверенность) независимо перепроверяет второй проход-«контролёр» и исправляет ошибку; в карточке видно, что подтверждено, а что исправлено и почему. На DEV: 228 перепроверок, 7 исправлений.
- **Проверка цитат.** Каждая цитата-доказательство сверяется кодом с реальным текстом реплики — выдуманная цитата помечается ⚠. На DEV: 1662/1667 цитат подтверждены.
- **Обучение на апелляциях.** Решение супервизора, изменившее оценку, становится прецедентом: ИИ получает его как пример трактовки правила в следующих оценках других диалогов (в тот же диалог не подмешивается — без утечки ответа). Список прецедентов — в «Настройках».
- **Коучинг оператора.** ИИ-наставник даёт 2–3 конкретных совета со ссылкой на реплику и готовой фразой на языке клиента.
- **Надёжность оценки** — в карточке: сколько цитат сверено, сколько ответов перепроверено и исправлено.
- **Умная переоценка** при смене чек-листа: ИИ вызывается только для изменённых критериев, вердикты супервизора сохраняются.
- **Метки доказательств в транскрипте** — у каждой реплики номера критериев, которые на неё ссылаются; клик открывает критерий.
- **Новый диалог вручную — текст или аудио.** Кнопка «+ Новый диалог»: вставьте транскрипт (`MM:SS спикер: текст`, есть примеры RU/KZ/EN) или загрузите запись звонка (mp3/wav/m4a/ogg, до 25 МБ). Для аудио сервер распознаёт речь через Whisper, LLM размечает роли говорящих (оператор/клиент/бот/система), запись прикрепляется к диалогу с плеером. Если роли выделены не полностью, транскрипт открывается для ручной проверки — повторно платить за распознавание не нужно. Диалоги попадают в набор `MANUAL`.

### Тесты для нового критерия
«Чек-листы» → «Правила ▸» у критерия → **🧪 Проверить критерий на тестах**. ИИ пишет 5–7 коротких диалогов с заранее известным ответом (каждое допустимое значение, один пограничный случай, RU/KZ/EN) и оценивает их этим критерием тем же путём, что реальные диалоги. Итог «ИИ понял критерий: 5 из 6» и разбор, где путается — до применения к реальным диалогам (~7 вызовов ИИ). Пример: на «Завершении» тест поймал, что «Рада была помочь! До свидания.» ИИ принимает за предложение помощи.

### Журнал для регулятора (цепочка хэшей)
Каждое сохранение чек-листа, оценки ИИ, решение супервизора и апелляция фиксируются в `audit_log`: отпечаток записи (SHA-256), сцепленный с предыдущим событием. «Аналитика → Журнал для регулятора → Проверить целостность» пересчитывает цепочку и сверяет текущие записи с отпечатками — правку базы в обход системы или подмену журнала видно сразу. Демонстрация: `py scripts/audit_demo.py tamper p1-ru-002` → проверка красная → `py scripts/audit_demo.py restore` → зелёная.

## Модель и стоимость

Модель задаётся в `.env`. Два провайдера на выбор:
- **Claude (Anthropic)** — `CQA_PROVIDER=anthropic`, `ANTHROPIC_API_KEY`, модель `CQA_CLAUDE_MODEL` (по умолчанию `claude-opus-5-5`), глубина рассуждения `CQA_CLAUDE_EFFORT`. Официальный SDK Anthropic, структурированный вывод по JSON Schema, кэширование транскрипта (`cache_control`), серверный fallback при отказе классификаторов безопасности. Стоимость оценки считается по ценам модели автоматически.
- **OpenAI-совместимый API** — `CQA_MODEL`.
- **Бесплатно: Google Gemini или Groq** — через тот же OpenAI-совместимый режим, готовые пресеты в `.env.example`. Для бесплатных тарифов: `CQA_EVAL_MODE=single` — все критерии одним вызовом (1 вызов на диалог вместо 8–12; некорректно возвращённые критерии дооцениваются по одному) и `CQA_RPM` — ограничение запросов в минуту с терпеливыми повторами при 429. Подходит любая модель с OpenAI-совместимым API:
- **облако:** OpenAI (по умолчанию `gpt-5.6-luna`; reasoning-модели без temperature поддерживаются автоматически);
- **локально:** Ollama, LM Studio или vLLM — достаточно задать `OPENAI_BASE_URL=http://localhost:11434/v1`.

На одну оценку уходит 8 вызовов LLM, по одному на критерий. Каждый вызов — это транскрипт и критерий (примерно 1,5–4 тыс. токенов на входе) и ответ (около 300 токенов на выходе). Кэширование промпта: системный промпт, JSON-схема ответа, транскрипт и факты одинаковы для всех критериев диалога; первый вызов идёт один и записывает этот префикс в кэш (для gpt-5.6+ — явная точка `prompt_cache_breakpoint`), остальные семь читают его из кэша. Замер на gpt-5.6-luna: из кэша берётся ~74% входных токенов. Для моделей без точек кэша включается обычное префиксное кэширование.

## Точность

Во вкладке «Сводка» показывается совпадение ответов ИИ с эталоном команды. Эталон размечается в карточке диалога: включите «Режим разметки эталона», и разметка сохранится в `gold/gold.json`. С ИИ сравниваются исходные ответы модели, то есть до апелляций.

## Интерфейс

Один файл `frontend/index.html` (HTML + CSS + JS, без сборки и фреймворков), корпоративный стиль в фирменном зелёном Freedom. Дизайн-система подобрана скиллом ui-ux-pro-max (стиль Data-Dense Dashboard, контраст текста ≥ 4.5:1, анимации 150–450 мс, `prefers-reduced-motion`).

- **Боковое меню:** Диалоги · Чек-листы · Апелляции · Аналитика; значки — число диалогов с грубыми ошибками (клик показывает их) и открытых апелляций; внизу — роль (Оператор/Супервизор) и загрузка набора по `group_id`.
- **Анализ разговора** — список с фильтрами (в т.ч. «Грубая ошибка») → транскрипт с **дорожками речи «Клиент / Оператор»** (клик по дорожке ведёт к реплике и месту в записи звонка, плеер) → карточка оценки: анимированное кольцо итога, секции, блок **«Почему снижена оценка»** с кнопками «Перейти к фрагменту» и «Оспорить оценку», критерии с обоснованием, доказательствами и расчётом.
- **Апелляции** — очередь для супервизора (ждут решения / решённые), «Рассмотреть» открывает диалог на спорном критерии; решение пересчитывает итог, исходная оценка ИИ сохраняется.
- **Чек-листы** — формулировка, тип, шкала, вес, N/A, правила для ИИ, код в выгрузке; «Применить» сохраняет версию и переоценивает диалоги.
- **Аналитика** — все грубые ошибки с объяснением и цитатой, распределение ответов, точность против эталона, сдача `results.json`.

Для встраивания как HTML web resource Dynamics 365 задайте `window.CQA_API_BASE` — адрес сервиса оценки.

## API (основное)

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/datasets/fetch` `{group_id}` | загрузить набор из API организаторов |
| POST | `/api/datasets/upload` | загрузить набор из JSON-файла |
| GET | `/api/conversations` | список диалогов с итогами |
| POST | `/api/conversations` `{conversation_id, channel, language, transcript, audio_file?}` | добавить диалог вручную (набор `MANUAL`) |
| POST | `/api/transcribe?language=AUTO` (multipart `file`) | аудио → Whisper → роли говорящих; возвращает транскрипт и `audio_file` |
| GET | `/api/conversations/{id}` | транскрипт, факты, оценка, апелляции |
| GET | `/api/conversations/{id}/audio` | редирект на свежую ссылку записи |
| POST | `/api/evaluate/{id}` | оценить один диалог |
| POST | `/api/evaluate` `{conversation_ids \| dataset, only_missing}` | пакетная оценка (фоновая задача) |
| GET/POST | `/api/checklists` | чек-листы, сохранение новой версии |
| POST | `/api/appeals` · `/api/appeals/{id}/decision` | подать апелляцию / принять решение |
| GET | `/api/gross` | диалоги с грубыми ошибками, объяснение и цитаты |
| GET | `/api/export` | выгрузка результатов (внутренний формат) |
| GET | `/api/results?dataset=DEV&use=ai` | results.json в формате организаторов (JSON 1.0) |
| POST | `/api/results/save?dataset=DEV` | записать `results/dev/…` или `results/prod/…` и проверить формат |
